# 撰寫模式

per W-1，writer 在 Stage 0 提供 3 種撰寫模式給使用者選擇。預設「逐章交付」。

## 模式 1: 逐章交付（預設）

### 適用情境

- 中長篇文章（3000+ 字）
- 文章涉及多個主題，每章邏輯獨立
- 使用者希望即時反饋寫作風格與方向

### 行為

```
For each chapter in structure:
  1. 寫該章
  2. 自檢
  3. 印出該章
  4. 等使用者「繼續」或反饋
  5. 反饋 → 修，沒反饋 → 進下一章
```

### 章節間 gate

每章寫完印給使用者後：

```markdown
**第 N 章寫完**：<章節名>（actual: 1240 字 / target: 1200 字）

[章節內容]

---

要繼續寫第 N+1 章「<下章名>」嗎？或這章要先修？
```

使用者明確說「繼續」「下一章」「continue」→ 進下章
使用者說具體修正 → 修改本章後重印
使用者說「停下」「先放著」→ 暫停，下次「繼續寫 <slug>」可接續

### 排程不支援

per W-2，逐章交付**不**支援排程觸發——必須有人在線回應。若排程觸發，writer 拒絕：

```markdown
偵測到排程模式但本 skill 需要 chapter-by-chapter 互動。長文寫作不能無人值守。
請手動觸發。
```

## 模式 2: 全文一氣呵成

### 適用情境

- 短篇（< 3000 字）
- 章節間內容連貫且短
- 使用者明確說「全部寫完再給我看」

### 行為

```
1. 依 structure 寫完所有章節（不停下）
2. 整篇自檢
3. 印整篇給使用者
4. 等反饋或進 Stage 3 落地
```

### 自檢與反饋

整篇寫完一次自檢。FAIL 自動修正後重印（不問使用者）。

整篇印給使用者後：

```markdown
**全文撰寫完成**：<title>（actual: 2840 字 / target: 3000 字）

[全文內容]

---

要進 Stage 3 落地（chain output-supervisor）嗎？或先修哪部分？
```

### 風險

整篇寫完才看，使用者若不滿意要全部重來，成本高。建議短文才用此模式。

## 模式 3: 先寫 outline 擴充

### 適用情境

- 使用者對方向不確定，想先看「擴充版的 structure」確認再展開
- 字數目標較大（10000+ 字），先寫 abstract 確認方向

### 行為

```
Phase 1: 擴充 outline
  - 對 structure 每章寫 200 字 abstract
  - 印整套 abstracts 給使用者
  - 使用者確認方向 OK 後進 Phase 2

Phase 2: 全文展開
  - 依擴充過的 outline 進「逐章交付」（同模式 1）或「全文一氣呵成」（同模式 2）
  - 使用者選擇 Phase 2 細節
```

### Phase 1 範例

```markdown
**擴充 outline（每章 200 字 abstract）**

### 1. 引言（800 字目標 → abstract 200 字）

本章從量子生物學的歷史脈絡切入：1944 年 Schrödinger 在 *What is Life?*
中提出生命可能涉及量子效應的猜想，但接下來六十年未有實驗證據。
2000 年代初期，光合作用 FMO 複合體的 2D 電子光譜實驗 [Engel, 2007] 
首次提供長壽命量子相干態的觀察，引發領域復興。本文聚焦於該復興後
十年的證據累積與爭議，目的是釐清此議題在 2026 年的知識狀態。

### 2. 理論背景（1200 字 → abstract 200 字）
...

### 3. 證據檢視（2000 字 → abstract 200 字）
...

[每章繼續]

---

整篇文章方向 OK 嗎？要進 Phase 2 全文展開嗎？或某章 abstract 要調整？
```

### Phase 2 行為

使用者確認 Phase 1 → 問選逐章交付還是全文一氣呵成 → 進對應行為。

## 模式選擇互動

Stage 0 結束時讓使用者選：

```markdown
我準備依下列架構撰寫：

[structure summary]

撰寫模式（請選一個）：

1. **逐章交付**（推薦）：每寫完一章停下，你說「繼續」我寫下一章。
   適合中長篇，可即時調整方向。
2. **全文一氣呵成**：寫完才停。
   適合短文（< 3000 字），少打斷。
3. **先寫 outline 擴充**：先把每章寫 200 字 abstract 給你看方向，再展開全文。
   適合對方向不確定的長文。

請選一個。沒選擇的話我用模式 1。
```

使用者明示後（「逐章」「全文」「outline」或其他同義）→ 確認進對應行為

## 切換模式（罕見）

寫到一半使用者要切換模式：

- 從逐章 → 全文：可（剩下章節一次寫完）
- 從全文 → 逐章：難（已寫完就是寫完，但下次有新主題的可選）
- 從 outline → 逐章/全文：自然發生（Phase 1 → Phase 2）

writer 接受切換指令但會確認：「目前已寫到第 3 章，要切換為全文一氣呵成（剩 4-7 章一次寫完）？」

## 失敗處理

任何模式下 Stage 3 自檢連續 3 次 FAIL → 停下提示使用者：

```markdown
我嘗試了 3 次自檢都有 CRITICAL FAIL：

- 第 1 次：失敗點 X
- 第 2 次：失敗點 Y
- 第 3 次：失敗點 Z

可能我對你期望的風格判斷不準。建議：

1. 你檢視當前草稿（drafts/<slug>.draft.md），告訴我具體哪裡不對
2. 或你指出 audit_checklist 哪條太嚴，我們調整 supervisor 規則
3. 或暫停，今天先存草稿，明天再來

要怎麼做？
```

不自動繼續嘗試（避免無限循環）。

## drafts/ 中途檔

所有模式下，writer 在寫作中保留 `drafts/<slug>.draft.md`：

- 每章寫完同步寫一份到 drafts
- Stage 3 落地時，drafts 仍保留（使用者可比對）
- drafts 不進 git（per W-5）
- internal-cataloger 會掃到 drafts 並顯示 status: drafting
