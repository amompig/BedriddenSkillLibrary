# documentation-and-adrs

> 架構決策紀錄（ADR）、API 文件、行內註解標準。重點是記錄「為什麼」，而不是重複「做了什麼」（那個看 diff 就知道）。

## 階段

**Ship — 有信心地上線**

## 用途

架構決策紀錄（ADR）、API 文件、行內註解標準。重點是記錄「為什麼」，而不是重複「做了什麼」（那個看 diff 就知道）。

## 觸發時機

做架構決策、修 API 契約、或 ship 重大功能時。

## 怎麼用

ADR 格式：Context / Decision / Consequences。每份 ADR 獨立檔、不改動歷史（若改變就寫新 ADR superseded 舊的）。
