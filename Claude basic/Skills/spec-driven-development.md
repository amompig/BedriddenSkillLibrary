# spec-driven-development

> 在寫任何程式碼前，先產出一份完整的 PRD（產品需求文件），包含目標、命令介面、結構、程式風格、測試策略、邊界案例。

**Slash command**：`/spec`

## 階段

**Define — 釐清要做什麼**

## 用途

在寫任何程式碼前，先產出一份完整的 PRD（產品需求文件），包含目標、命令介面、結構、程式風格、測試策略、邊界案例。

## 觸發時機

啟動新專案 / 新功能 / 任何重大變更之前；或是當現有規格模糊到 Claude 必須不斷猜測意圖時。

## 怎麼用

輸入 `/spec` 觸發。Skill 會生成 spec.md，裡面分章節列出 Goals / CLI / Structure / Style / Testing / Edge cases。寫完規格再開始實作。
